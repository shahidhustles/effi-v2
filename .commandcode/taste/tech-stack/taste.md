# tech-stack
- Use PNPM + Turborepo monorepo workspace; apps (officer-dashboard, citizen-app, bot gateway) live in `apps/` while stable domain/platform boundaries go in `packages/`. Confidence: 0.80
- Use Convex as the shared backend and Clerk for authentication; Convex is the durable single source of truth for reports and acknowledgement state. Confidence: 0.80
- Clerk Core 2 JWT templates cannot set the `aud` claim (it is reserved/stripped), so Convex's standard `domain + applicationID` auth provider rejects those tokens; the working pattern is Convex's `customJwt` provider validated by issuer + JWKS (`CLERK_JWT_ISSUER_DOMAIN` + `/.well-known/jwks.json`, RS256). Confidence: 0.8
- Client components that fire authenticated Convex mutations must gate them on `useConvexAuth()` readiness (`isLoading === false && isAuthenticated === true`); firing on mount before Clerk hydrates and `ConvexProviderWithClerk` attaches the token sends the request anonymous (no Authorization header) and Convex rejects it with a "Sign in" error. Confidence: 0.7
- Use TypeScript with strict mode enabled across the workspace. Confidence: 0.75
- Next.js App Router projects with Clerk need a root-level middleware file registering `clerkMiddleware()` for server-side `auth()`; in this repo (Next 16) that file is `proxy.ts` at the app root, not `src/`, and it uses Clerk's standard broad matcher — narrow route-scoped matchers break Clerk's internal sign-in/`sso-callback` subroutes, and `<SignIn/>` mounted on a dynamic route must sit under a catch-all `[[...rest]]` segment. Confidence: 0.7
- Eve (`eve/tools`) agent tools that return a user-facing message (e.g., `recipientMessage`) must define `toModelOutput` presenting the exact text the model should send; without it the model receives the raw result object and (on weaker models like `qwen3.7-flash`) re-calls the tool, causing duplicate "Approve tool call" prompts before the message is delivered. Confidence: 0.6
